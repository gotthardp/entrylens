## Per-pin requirements

| Pin | Name | Requirement |
|---|---|---|
| 1 | PA3/UART2_RX | Reserved - UART2/LPUART1 interface (AT commands and firmware update). |
| 2 | PA2/UART2_TX | Reserved - UART2/LPUART1 interface (AT commands and firmware update). |
| 3 | PA15/PIN_A4 | GPIO and ADC. **JTAG JTDI**: input with internal pull-up after reset, until firmware reconfigures it; usable as GPIO once firmware selects SWD-only. |
| 4 | PB6/UART1_TX | UART1 interface. |
| 5 | PB7/UART1_RX | UART1 interface. |
| 6 | PA1 | GPIO only. |
| 7 | PA13/SWDIO | Reserved - SWD debug pin (SWDIO); JTAG JTMS. Input with internal pull-up after reset. |
| 8 | PA14/SWCLK | Reserved - SWD debug pin (SWCLK); JTAG JTCK. Input with internal pull-down after reset. |
| 9 | PA12/I2C_SCL | GPIO and I2C (SCL). |
| 10 | PA11/I2C_SDA | GPIO and I2C (SDA). |
| 11 | GND | Ground. |
| 12 | RF  | RF Port, not available on IPEX variant. |
| 13 | PA7 | SPI1 (MOSI). |
| 14 | PA6 | SPI1 (MISO). |
| 15 | PA5 | SPI1 (CLK). |
| 16 | PA4 | SPI1 (NSS). |
| 17 | GND | Ground. |
| 18 | GND | Ground. |
| 19 | PA8 | GPIO only. |
| 20 | PA9 | GPIO only. |
| 21 | BOOT0 | Boot0 mode enable pin, high active (MCU pin PH3-BOOT0). Per a RAK staff forum clarification (see header above), BOOT0 is pulled down internally by the module - no external strap is required. The pin is an input during reset until at least the end of option-byte loading; option bytes nSWBOOT0 = 0 and nBOOT0 = 1 make the boot selection ignore it. |
| 22 | RST | MCU reset (NRST). |
| 23 | GND | Ground. |
| 24 | VDD | Voltage supply. |
| 25 | PA10/PIN_A3 | GPIO and ADC. |
| 26 | PB2/PIN_A2 | GPIO and ADC. |
| 27 | PB12 | 10 kOhm internally pulled up for the high-frequency variant, or pulled down for the low-frequency variant. |
| 28 | GND | Ground. |
| 29 | PA0 | GPIO only. |
| 30 | PB5 | GPIO only. |
| 31 | PB4/PIN_A1 | GPIO and ADC. **JTAG NJTRST**: input with internal pull-up after reset, until firmware reconfigures it; usable as GPIO once firmware selects SWD-only. The pull-up makes it unsuitable for a signal that must be low before firmware runs. |
| 32 | PB3/PIN_A0 | GPIO and ADC. **JTAG JTDO / TRACESWO**: Hi-Z, no pull after reset; usable as GPIO once firmware selects SWD-only. Becomes an output if a debugger enables single-wire trace (SWO). |

I/O state after reset (RM0461 8.3.1): "most of the I/O ports are configured in analog mode" (no
pull). The exceptions are the five SWJ debug pins noted above (PA13, PA14, PA15, PB3, PB4), which
are in debug alternate-function mode with the pulls listed, and PH3-BOOT0 (pin 21).
JTAG is selected by default after reset; in SW-DP mode "the unused JTAG pins JTDI, JTDO and nJTRST
can be used for other functions" (36.3.6), and reconfiguring PA13/PA14 disables debugging. The
internal weak pull-up/pull-down is 25 to 55 kOhm (`stm32wle5cc.pdf`, I/O static characteristics,
RPU/RPD).

## Electrical limits and consumption

| Parameter | Value | Conditions |
|---|---|---|
| VDD (main supply voltage) | -0.3 to 3.9 V | Absolute maximum |
| VDD (standard operating voltage) | 2.0 to 3.6 V | Recommended operating condition |
| Operating current, TX | 87 mA to 120 mA | 868 MHz; 87 mA at 20 dBm (RAK module datasheet), 120 mA at +22 dBm (`stm32wle5cc.pdf` Table 29, radio only, typ) |
| Operating current, RX | 5.22 mA | |
| VOH (output high level) | >= VDD - 0.4 V | CMOS port, IIO = 8 mA, VDD >= 2.7 V |
| VOH (output high level) | >= 2.4 V | TTL port, IIO = 8 mA, VDD >= 2.7 V |
| VOH (output high level) | >= VDD - 1.3 V | IIO = 20 mA, VDD >= 2.7 V |
| VOL (output low level) | <= 0.4 V | CMOS port, IIO = 8 mA |
| VOL (output low level) | <= 1.3 V | IIO = 20 mA |
| Output current sunk by any I/O or control pin | 20 mA | Absolute maximum |
| Output current sourced by any I/O or control pin | 20 mA | Absolute maximum |
| Total output current sunk, sum of all I/Os and control pins | 100 mA | Absolute maximum, must be distributed over all I/Os |
| Total output current sourced, sum of all I/Os and control pins | 100 mA | Absolute maximum, must be distributed over all I/Os |
| Operating temperature range | -20 to 85 degC | |

## Known limitations of the STM32WLE5 die (ES0506 Rev 5)

The module datasheet carries no errata of its own; these are limitations of the STM32WLE5 inside it.
Only the ones this design can hit are listed. Status is given for silicon Rev Z and Rev Y; the
module's silicon revision is not stated by RAK and has not been confirmed.

| Section | Status | Limitation | Workaround |
|---|---|---|---|
| 2.7.1 | P / P | Wrong data sampling when the I2C data setup time tSU;DAT is shorter than one I2C kernel clock period: the previous SDA value is sampled instead of the current one, giving a wrong target address, data byte or acknowledge bit | Raise the I2C kernel clock so its period fits inside the transmitter's minimum setup time. **In Fast-mode Plus, for the standard 50 ns minimum, I2CCLK must be at least 20 MHz** (Fast mode 10 MHz, Standard mode 4 MHz) |
| 2.2.6 | A / A | The 1.2 V regulated supply can dip to 1.08 V when MSI steps from 400 kHz to 24 MHz or above, or from 1 MHz to 48 MHz, which can cause a CPU HardFault. Reached by way of 2.7.1, which forces a higher kernel clock | Step through an intermediate MSI frequency, e.g. 400 kHz -> 12 MHz -> 48 MHz |
| 2.2.2 | N / N | Re-programming a flash location that currently holds all ones with all zeros fails and sets PROGERR. Erased locations are unaffected | None. Avoid all-zeros-over-all-ones as a marker pattern |
| 2.2.5 | A / A | FLASH_ECCR can be corrupted if a reset or power-down happens during a flash program or erase and the same location is then read | Erase the page(s) covering that location |
| 2.2.14 | A / A | TX spurs around the carrier at multiples of the HSE clock frequency | See ES0506. Bears on EN 300 220 spurious emissions |
| 2.2.18 | A / A | Packet loss with inverted IQ operation, which LoRaWAN downlinks use by specification | See ES0506 |
